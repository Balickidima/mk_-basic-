# 🔧 Отладка STM32 в PlatformIO — Полное руководство

## 📋 Что было сделано для отладки

### 1. Новый toolchain GCC 14.x

**Проблема:** Старый GCC 7.x не поддерживал современные функции отладки.

**Решение:** В `platformio.ini` добавлено:
```ini
platform_packages =
    platformio/toolchain-gccarmnoneeabi@^1.140201.0
```

Это устанавливает **GCC 14.2.1** с **GDB 9+**, который поддерживает:
- ✅ DWARF 4 (лучшая отладка)
- ✅ Переменные в реальном времени
- ✅ Условные точки останова
- ✅ Трассировка выполнения

---

### 2. Исправление флагов ассемблера (`fix_asflags.py`)

**Проблема:** Новый GCC 14.x не понимает флаги `-g3`, `-ggdb` для ассемблера.

**Решение:** Скрипт `fix_asflags.py` автоматически убирает флаги отладки из ASFLAGS:

```python
# Убираем все флаги начинающиеся с -g
filtered = [f for f in current_asflags if not f.startswith("-g")]
env.Replace(ASFLAGS=filtered)
```

**Как работает:**
- Запускается **после** сборки (`post:fix_asflags.py`)
- Фильтрует ASFLAGS перед компиляцией ассемблерных файлов (.s/.S)
- Выводит лог о изменении флагов

### 3. Конфигурация VS Code для отладки

#### `.vscode/launch.json`

Содержит **5 конфигураций** отладки:

| Конфигурация | Описание |
|-------------|----------|
| **Debug (OpenOCD)** | Основная — отладка через cortex-debug с OpenOCD |
| **Attach (OpenOCD)** | Подключение к работающей программе |
| **PIO Debug** | Отладка через PlatformIO (автоматическая сборка) |
| **PIO Debug (skip Pre-Debug)** | Без предварительной сборки |
| **PIO Debug (without uploading)** | Без загрузки в MCU (ручная загрузка) |

**Ключевые настройки Debug (OpenOCD):**
```json
{
    "serverpath": "C:/Users/.../tool-openocd/bin/openocd.exe",
    "configFiles": [
        "interface/stlink.cfg",
        "target/stm32f4x.cfg"
    ],
    "searchDir": ["C:/Users/.../tool-openocd/openocd/scripts"],
    "runToEntryPoint": "main",
    "svdFile": "${workspaceFolder}/STM32F401cc.svd"
}
```

#### `.vscode/settings.json`

Настройки **cortex-debug** расширения:

```json
{
    "cortex-debug.gdbPath": ".../arm-none-eabi-gdb.exe",
    "cortex-debug.openOCDPath": ".../openocd.exe",
    "cortex-debug.swoEnabled": true,  // ITM/SWO вывод
    "cortex-debug.swoConfig": { ... } // Настройки SWO
}
```

### 4. Настройки отладки в platformio.ini

```ini
[env:debug]
build_flags =
    -O0           ; Без оптимизации
    -g3           ; Максимальная отладочная информация
    -ggdb         ; GDB расширения
    -gdwarf-4     ; DWARF формат 4
    -fno-omit-frame-pointer  ; Сохранять frame pointer

build_unflags =
    -g2           ; Убираем стандартные флаги
    -g3
    -ggdb2
    -ggdb3

debug_tool = stlink
debug_server =
    -g
    -ex set mi-async off
debug_init_break = tbreak main  ; Точка останова на main()
```

## 🚀 Как использовать отладку

### Шаг 1: Подготовка

1. Убедитесь, что установлены расширения VS Code:
   - **PlatformIO IDE**
   - **Cortex-Debug** (обязательно!)
   - **C/C++** (рекомендуется)

2. Проверьте, что путь к OpenOCD правильный в:
   - `platformio.ini` → `upload_command`
   - `.vscode/launch.json` → `serverpath`, `searchDir`
   - `.vscode/settings.json` → `cortex-debug.openOCDPath`

3. Скомпилируйте проект:
   ```bash
   pio run -e debug
   ```

---

### Шаг 2: Запуск отладки

#### Вариант 1: Через Cortex-Debug (рекомендуется)

1. Откройте файл `main.c`
2. Поставьте точки останова (F9)
3. Нажмите **F5** или перейдите на вкладку "Run and Debug"
4. Выберите **"Debug (OpenOCD)"**
5. Нажмите ▶️

**Что произойдёт:**
- PlatformIO скомпилирует проект (если нужно)
- OpenOCD подключится к ST-Link
- Прошивка загрузится в MCU
- Выполнение остановится на `main()`

#### Вариант 2: Через PlatformIO

1. Откройте терминал PlatformIO (Ctrl+Alt+P)
2. Введите: `PlatformIO: Debug`
3. Выберите конфигурацию

---

### Шаг 3: Процесс отладки

#### Основные действия:

| Клавиша | Действие |
|---------|----------|
| **F5** | Продолжить выполнение |
| **F9** | Точка останова |
| **F10** | Шаг через функцию |
| **F11** | Шаг в функцию |
| **Shift+F11** | Шаг из функции |
| **Ctrl+Shift+F5** | Перезапуск отладки |

#### Окна отладки:

- ** VARIABLES** — переменные (локальные, глобальные)
- **WATCH** — отслеживаемые выражения
- **CALL STACK** — стек вызовов
- **BREAKPOINTS** — точки останова
- **PERIPHERALS** — периферия (через SVD файл)
- **DEBUG CONSOLE** — команды GDB

---

### Шаг 4: ITM/SWO вывод (printf в реальном времени)

Если используете **ITM/SWO** для вывода:

1. В коде используйте `ITM_SendChar()` или `printf()` через ITM
2. В отладке откройте окно **"SWO"**
3. Выберите порт (обычно порт 0)

**Пример:**
```c
#include "stm32f4xx.h"

void ITM_SendString(char *str) {
    while (*str) {
        ITM_SendChar(*str++);
    }
}

// В main()
ITM_SendString("Hello from STM32!\n");
```

## ⚠️ Частые проблемы

### 1. "Cannot find GDB"

**Причина:** Не установлен toolchain или неправильный путь.

**Решение:**
```bash
pio pkg install --toolchain
```

Или проверьте путь в `.vscode/settings.json`:
```json
"cortex-debug.gdbPath": "C:/Users/.../arm-none-eabi-gdb.exe"
```

---

### 2. "OpenOCD can't connect"

**Причина:** ST-Link не подключён или драйверы не установлены.

**Решение:**
1. Проверьте подключение ST-Link
2. Установите драйверы ST-Link
3. Проверьте, что SWD интерфейс подключён (GND, SWDIO, SWCLK, 3.3V)

---

### 3. "Breakpoint not hit"

**Причина:** Оптимизация кода или неправильные флаги.

**Решение:**
Убедитесь, что в `platformio.ini` есть:
```ini
build_flags =
    -O0
    -g3
    -gdwarf-4
    -fno-omit-frame-pointer
```

---

### 4. "ASFLAGS error" после обновления

**Причина:** Новый GCC не понимает старые флаги.

**Решение:**
Убедитесь, что `fix_asflags.py` подключен:
```ini
extra_scripts =
    pre:extra_script.py
    post:fix_asflags.py
    post:copy_artifacts.py
```

---

### 5. "Cortex-Debug extension not found"

**Причина:** Не установлено расширение.

**Решение:**
1. Откройте Extensions (Ctrl+Shift+X)
2. Найдите **"Cortex-Debug"**
3. Установите
4. Перезапустите VS Code

## 💡 Советы по отладке

### 1. Используйте conditional breakpoints

Вместо остановки на каждом шаге:
```
break main if counter > 10
```

### 2. Watch expressions

Добавьте в WATCH окно:
- `*peripheral_register` — значение регистра
- `array@10` — первые 10 элементов массива
- `*((uint32_t*)0x40020000)` — значение по адресу

### 3. Memory View

Откройте **Memory View** для просмотра памяти:
```
0x20000000  ; Начало RAM
0x08000000  ; Начало Flash
```

### 4. Call Stack

Смотрите **CALL STACK** чтобы понять цепочку вызовов.

### 5. Peripheral View

Используйте **SVD файл** для просмотра периферии:
- GPIO регистры
- Таймеры
- USART
- И т.д.
